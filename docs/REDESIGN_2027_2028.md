# Redesign identitas Khairul Falah 2027/2028

## Audit dan keputusan implementasi

- Basis: repository `wahidhas/khairulfalah`, commit `8fd9dbe`. Branch kerja: `codex/brand-identity-2027-2028`.
- Dokumen yang diperiksa: AGENTS, README, PROJECT_CHARTER, DESIGN_SYSTEM, CONTENT_STRATEGY, INFORMATION_ARCHITECTURE, SRS; halaman, konfigurasi, konten homepage, serta komponen layout/section.
- Brief identitas 2027/2028 menggantikan positioning dan navigasi lama. Aturan arsitektur, aksesibilitas, performa, serta pola content-driven tetap dipakai.
- Komponen yang digunakan kembali: MainLayout, Container, Section, Button, Card, IconBox, Breadcrumb, FAQItem, registry Lucide, helper kontak dan SEO. Tidak ada framework/dependency baru, perubahan backend, autentikasi, atau pengumpulan data anak.
- Homepage menjadi pintu masuk Yayasan dengan MI dan MTs berimbang. MI berfokus pada adab, ibadah, karakter, dan life skills; MTs pada Digital Creator berlandaskan Al-Qur’an dan adab. Nama administratif tetap MI Khairul Falah dan MTs Khairul Falah.
- Halaman lama dipertahankan. `/ppdb` menjadi pusat SPMB; fragment `#alur-pendaftaran` dan `#kontak-ppdb` tetap tersedia. Slug artikel pengumuman lama tetap sama.
- RA diarahkan ke informasi admin pada `/contact#ra`, tanpa mengarang nama/program/penerimaan RA.
- Student Growth Portal hanyalah mockup statis berlabel pengembangan, tanpa data pribadi atau fungsi login. Jalur belajar MTs dan empat program digital diberi label rancangan/pengembangan. Portofolio kosong memiliki status yang jelas.
- Ruang belajar MI dipresentasikan sebagai arah pengalaman belajar; kesiapan fasilitas dan jadwal tidak diklaim sudah tersedia.

## SEO dan kompatibilitas

- Judul/deskripsi lokal Bekasi untuk homepage, MI, MTs, dan SPMB; title lengkap tidak diberi suffix brand ganda.
- Canonical memakai domain produksi, termasuk pada preview. Konfigurasi Vercel lama ternyata masih memuat domain `.sch.id`; canonical sekarang memakai satu sumber pada `src/config/site.ts` dan mengabaikan PUBLIC_SITE_URL lama. Domain telah diperbaiki menjadi `https://khairulfalah.my.id`.
- Open Graph/Twitter menggunakan gambar kampanye. Schema Organization, WebSite, School, BreadcrumbList, dan FAQ hanya memuat data yang tersedia; logo tidak masuk schema bila file belum ada.
- Sitemap Astro otomatis mencakup rute baru. Build dengan `VERCEL_ENV=preview` menghasilkan meta noindex dan robots Disallow; production tidak diubah.

## Pengujian

```powershell
$env:ASTRO_TELEMETRY_DISABLED='1'
npm ci
npm run check
npm run build
node scripts/verify-site.mjs
npm run preview -- --host 127.0.0.1
```

`ASTRO_TELEMETRY_DISABLED` menghindari penulisan konfigurasi telemetry di luar workspace; bukan perubahan aplikasi.

- Check awal: 0 error, 0 warning, 7 hint lama dari komponen dasar/font onload.
- Build: berhasil, 24 halaman statis.
- Verifikasi output: 24 halaman HTML, 1127 tautan/aset lokal, 44 gambar; heading utama, metadata, canonical, JSON-LD, fragment, sitemap, dan rute lama lulus.
- Browser bawaan tidak dapat mengakses localhost; pemeriksaan visual dilakukan pada preview Vercel. Enam halaman diuji pada 320, 390, 768, 1024, 1280, dan 1440 piksel: 36 pemeriksaan tanpa overflow horizontal/gambar rusak.
- Menu mobile, dropdown desktop, Escape/fokus kembali, FAQ, dan alur homepage → MI → SPMB diuji. Tidak ada console error pada sesi uji. WhatsApp resmi dari konfigurasi Vercel terbaca; CTA per jenjang menggunakan pesan yang sesuai tanpa mengirimkannya.
- Delapan screenshot viewport homepage, MI, MTs, dan SPMB disimpan pada `docs/screenshots/`, ditambah portal, journey, dan portofolio. Capture full-page browser tidak tersedia pada sesi ini. Lihat [galeri preview](REDESIGN_PREVIEW.md).
- Check akhir: 0 error, 0 warning, 7 hint. Lighthouse dan audit WCAG lengkap belum diukur.
- Audit dependency bawaan repository: npm melaporkan 11 kerentanan (10 high, 1 critical), termasuk Astro 7.1.3. `package.json`/lockfile tidak diubah dalam redesign ini. Perlu pembaruan dependency dan audit ulang sebelum publikasi production; angka ini bukan penilaian eksploitabilitas situs statis.

## Keputusan Yayasan sebelum publikasi

1. Sahkan copy identitas, status program, kesiapan fasilitas, dan rancangan jalur belajar.
2. Setujui foto/logo/karya asli beserta izin publikasinya dan favicon resmi.
3. Sahkan informasi SPMB dan kontak panitia; aktifkan formulir hanya setelah URL valid tersedia.
4. Tinjau desktop, tablet, mobile, serta audit aksesibilitas/performa pada preview. Target Lighthouse/WCAG tidak diklaim lulus tanpa pengukuran.
5. Jadwalkan pembaruan keamanan dependency bawaan, lalu review ulang sebelum merge/publikasi.

Tidak ada merge atau deployment production yang diotorisasi oleh brief. Preview pada branch terpisah merupakan hasil untuk ditinjau Yayasan.
